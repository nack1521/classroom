# Gate 0 independent review 005 — local correction not accepted yet

**Reviewed:** 2026-09-25  
**Branch:** `fix/gate0-auth`  
**Scope:** Handoff 005's implementation and tests, excluding Hermes's separate planning/review edits. No real accounts, secrets, roster, cloud config, commit, push or deployment used in the review.

## Reproduced progress

- Fresh `npm run test` passed **45/45**, `npm run lint`, `npm run typecheck`, `npm run build`, and `git diff --check` passed. A second test run after the fresh build passed 45/45. The local Auth stub intentionally returns HTTP 401 for a forged token; this is expected test output.
- The built Nuxt server's `/protected` route was exercised with synthetic cookie sessions. An independent reviewer also drove overlapping local HTTP requests and observed the default middleware → production `useAuth()` → request-scoped Supabase client → `getUser()` path: valid student/teacher sessions got separate 200 responses, absent/forged sessions got 302, and a forged user object inside a cookie was not trusted over the Auth stub's response. This proves a **local controlled-stub SSR boundary**, not Google OAuth, Supabase-hosted Auth, enrollment, or RLS.
- `app/utils/supabaseClient.ts:71-77` disables automatic browser URL detection. An independent controlled-client probe of the installed SDK observed zero automatic PKCE exchanges during initialization and one during the explicit callback; the previous double-exchange concern is resolved in that probe, though the repo has no durable browser-SDK callback test yet.
- Callback failures for an absent code, reused code rejected by the mocked provider, null exchange session, and missing/failed token setup are now covered by tests. The previous process-global processed-code cache is gone. An in-flight successful-sign-out race test now waits for `getUser()` to start.

## Remaining blockers

1. **Callback identity is not bound to the exchanged identity.** `app/utils/auth.ts:349-417` verifies that the exchange returned some session/user, then calls `getUser()` and returns *whichever* verified user it finds without comparing IDs. Independent synthetic probe: exchange returned `new-user`, `getUser()` returned pre-existing `old-user`, and callback returned `{success:true, user.id:'old-user'}`. This violates the stated fail-closed acceptance rule. It is a proven logic gap; occurrence in a normal Supabase OAuth round-trip is not established.
2. **Sign-out policy contradicts the installed SDK.** `app/composables/useAuth.ts:161-165,181-190` claims that a provider sign-out error leaves `user.value` intact. In the installed `@supabase/auth-js/dist/module/GoTrueClient.js:3435-3453`, a non-ignored remote error still calls `_removeSession()` before returning the error; `_removeSession()` erases local storage and emits `SIGNED_OUT` (`:4418-4435`). The event handler at `app/utils/auth.ts:246-249` clears the UI. A separate reviewer reproduced the remote-500 path with a local endpoint: `signOut()` returned failure but both local session and UI user were null. The mock at `tests/review002-integration.test.ts:446-493` omits that SDK event, so it falsely supports the stated retain-user policy. Decide and test an honest outcome for local sign-out with remote revocation failure: clear local identity and warn that remote revocation is unconfirmed; do not claim the local persisted session remains active when the SDK removed it.
3. **Token/code scrubbing is claimed but not implemented.** `app/utils/auth.ts:304-310,358-363,387-391,404-409` carries provider/error message text into the callback result; `app/pages/auth/callback.vue:11-12,48` displays it. With a synthetic error message containing a marker also used as the callback code, a local probe found the marker in the returned error (`error_exposes_callback_code:true`). No real secret was seen or logged in this review. Avoid surfacing arbitrary provider descriptions or SDK errors without redaction; expose a safe generic message and retain only non-sensitive categories.

## Test-evidence limitation

- `tests/regression-review001.test.ts:351-352,380-383,485-509` silently returns from all four built-server tests if `.output/server/index.mjs` is missing, yet Vitest counts them as passing. On this machine the fresh build exists and the controlled-stub HTTP path was exercised, but `npm run test` on a clean clone can misleadingly report the same pass count without testing that boundary. Require a fresh build or fail/explicitly skip the suite; do not label a skipped HTTP suite as integrated verification. The test's `Promise.all` alone also does not assert request overlap (`:513-526`), though a separate instrumented local probe did observe overlap.

**Decision:** Gate 0 local implementation remains unaccepted pending the three blockers and repeatable built-artifact test. Do not merge/push this correction branch as verified. A real authorized school-Google sign-in and hard reload remain separate external gates; no user credentials should be sent through chat.
