## Bounded corrections

1. **Bind callback success to the current exchanged user.** On PKCE exchange or token-session setup, do not report success if the subsequent verified `getUser()` identifies a different person than the new exchange/setup user. Require a meaningful matching identity (and session) from the same callback; a pre-existing session must never make a mismatched callback look successful. Add a regression that first fails with exchange=`new-user`, `getUser`=`old-user`, then passes after the fix. Keep current rejection of reused/empty/invalid code, null session, and missing/failed `setSession`. Add a durable, controlled-SDK browser test showing `detectSessionInUrl:false` means no automatic exchange and exactly one explicit exchange; no real accounts.
2. **Handle failed remote sign-out according to actual SDK behavior.** The installed auth-js removes local session and emits `SIGNED_OUT` even for some remote sign-out errors. Use a controlled local Auth endpoint with the actual SDK and its auth-state notification to test the remote-500 path; a mock that merely returns `{error}` is insufficient. Recommend clearing local identity as the SDK does, keeping the user on a page that displays a safe warning that remote revocation could not be confirmed, and never claiming that a local persisted session necessarily remains active. Also preserve the already-proven in-flight verification invalidation. Document the distinction between local session removal and remote revocation status.
3. **Do not expose callback codes/tokens through errors.** Provider `error_description` and SDK error messages may echo sensitive query/hash values. Return safe generic messages or allowlisted non-sensitive categories; test with synthetic markers that no code/token marker appears in callback results or visible UI. Do not log raw URL, code, tokens, cookies, or secrets.
4. **Make built-app tests fail closed.** `tests/regression-review001.test.ts` currently counts four HTTP tests as passing when `.output/server/index.mjs` is absent. Require a fresh build in a dedicated integration command/setup, or fail explicitly with instructions, and prove the suite cannot silently pass against a missing/stale build. If claiming concurrent overlap, instrument a delayed local Auth stub and assert requests overlap rather than using only `Promise.all`. Keep valid/missing/forged cookie assertions through the real default Nuxt middleware.
