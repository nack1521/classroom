## Row B: independent review and correction of evidence

Antigravity's 006F1 test removed manual private `_notifyAllSubscribers` calls and used installed `GoTrueClient.setSession()` to emit `SIGNED_IN` naturally. An independent reviewer found three evidentiary gaps in the first 006F1 test: request #2 was named from counting alone, production `INITIAL_SESSION` might overlap, and checking final `user.value` could miss a transient restoration before `SIGNED_OUT`. Hermes made **test-only** changes to `tests/diagnostic-006f-row-b.test.ts`, without changing production:

- Wait for a null `INITIAL_SESSION` and a separate null assignment by the production listener before `setSession`; assert no `/user` traffic at that boundary. The installed SDK's `_setSession()` performs internal `_getUser` before emitting natural `SIGNED_IN` (`GoTrueClient.ts:3646-3659`).
- Wrap the public `client.getUser()` with a call-through spy (no invented response) and assert exactly one call while the second `/user` request is held. This ties request #2 to production `useAuth` verification rather than the SDK's pre-event `_getUser`. A bounded wait replaces the unbounded deferred-request promise.
- Track every authenticated assignment after `auth.signOut()` starts, wait for the app-wired `getUser` call to settle, then assert **no** transient restoration and a null final state. The generation counter is proved to increment before the held response is released. A separate uninterrupted natural-event positive control still populates the verified user.

## Explicit residual risk and exclusions

- **Six stress RED cases remain:** five 006E5C injected sign-out/SDK-response anomalies and one 006F A2 custom cookie adapter deliberately ignoring all deletion. They are skipped in the ordinary suite but runnable with `GATE0_STRESS=1` (prior independent results: 5 RED and 1 RED respectively). **Skipped does not mean passed.** A2 does not establish that the application's actual `document.cookie`/H3 `setCookie` adapter fails. If a retained ambiguous session is reproduced with that supported adapter, reopen Gate 0 immediately. Do not delete these tests; review them at a later release/hardening gate.

Those require separate acceptance gates. No new permission to use real student records is implied.
